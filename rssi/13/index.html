Funcionamento detalhado do DNS e DHCP

A Camada de Aplicação (L7)

Chegamos ao topo do Modelo OSI. É aqui que o usuário e o software interagem com a rede.

L1 a L3: Cabos e IPs (A Estrada)
L4: TCP/UDP e Portas (Os Caminhões)
L7: Aplicação (A Carga/Pacote)

A Camada 7 fornece serviços de rede aos aplicativos do usuário (como o Chrome, Outlook ou um Jogo).

Os Pilares da Automação

Sem os dois protocolos que vamos estudar hoje, usar a internet seria um trabalho manual infernal.

DNS

Domain Name System

Traduz nomes fáceis de lembrar em endereços IP de máquinas.

DHCP

Dynamic Host Configuration Protocol

Atribui IPs automaticamente aos dispositivos que se conectam.

Parte 1: DNS

A Lista Telefônica da Internet

Por que precisamos do DNS?

Os computadores só sabem comunicar usando Endereços IP (ex: 142.250.190.46). Mas a mente humana é péssima para memorizar números.

O que você digita

google.com

→

O que o PC precisa

142.250.190.46

O DNS faz essa tradução em milissegundos, de forma invisível.

A Estrutura de um Domínio (FQDN)

A internet é hierárquica. Lê-se um domínio da direita para a esquerda.

www . google . com .
  • . (Ponto final invisível): O "Root" (Raiz) da internet.
  • .com : O Top-Level Domain (TLD). Indica a categoria comercial.
  • google : O Domínio de Segundo Nível. É o que a empresa compra.
  • www : O Subdomínio ou Hostname (nome da máquina específica).

Exemplo 2: Domínio Acadêmico

Vamos analisar um FQDN (Fully Qualified Domain Name) com mais níveis hierárquicos.

www . cotil . unicamp . br .
  • . (Ponto final): O Root (Raiz).
  • .br : TLD de código de país (Brasil).
  • unicamp : Domínio de 2º Nível (A Universidade).
  • cotil : Subdomínio de 3º Nível (O colégio técnico).
  • www : O Hostname final (O servidor web do colégio).

A Hierarquia dos Servidores DNS

Nenhum servidor no mundo tem todos os IPs gravados. O trabalho é dividido.

1. Root Servers (Raiz)

Existem 13 clusters no mundo. Eles não sabem o IP do Google, mas sabem quem controla os `.com` ou `.br`.

2. Servidores TLD

Controlam os finais (`.com`, `.pt`, `.br`). Eles dizem: "O domínio unicamp.br foi registrado por X servidor".

3. Servidores Autoritativos

É o servidor final, mantido pela própria empresa/instituição. É ele que tem a resposta final e afirma: "Sim, o meu servidor www tem o IP 142.x.x.x".

O Resolvedor do ISP (DNS Resolver)

O seu computador não fala diretamente com os Root Servers. Ele pede a um Resolvedor.

O Resolvedor é normalmente fornecido pelo seu Provedor de Internet - ISP (Claro, Vivo, Oi) ou você pode usar um público (Ex: 8.8.8.8 da Google, 1.1.1.1 da Cloudflare).
1
O PC faz uma consulta recursiva: "Qual o IP do pudim.com.br?"
2
O Resolvedor faz o trabalho iterativo: pergunta ao Root, que manda para o TLD, que manda para o Autoritativo.
3
O Resolvedor devolve a resposta ao PC e guarda em cache para a próxima vez ser mais rápido.

Tipos de Registros DNS (Records)

A tabela do servidor Autoritativo tem várias colunas. As principais são:

TipoSignificadoExemplo prático
AAddress (IPv4)Mapeia `www.site.com.br` para `192.168.1.5`
AAAAIPv6 AddressMapeia `www.site.com.br` para `2001:db8::1`
CNAMECanonical NameUm "apelido". Faz `loja.site.com.br` apontar para `www.site.com.br`
MXMail ExchangeDiz qual é o servidor de E-mail responsável por receber mensagens.
TXTText RecordTexto livre. Muito usado para comprovar segurança (SPF, DKIM).

DNS na Camada de Transporte

Porta 53

Padrão: UDP (Consultas Rápidas)

Por que UDP? Porque uma consulta DNS é minúscula. Se falhar, é mais rápido enviar a pergunta de novo do que criar todo um "Three-Way Handshake" do TCP.

Exceção: Zone Transfer (Transferência de Zona via TCP 53)
Quando dois servidores DNS (um Primário e um Secundário) precisam sincronizar o banco de dados inteiro, eles utilizam o TCP. Como o volume de dados é grande e não pode haver desordem na tabela, a robustez do TCP torna-se obrigatória.

Parte 2: DHCP

Configuração Mágica e Automática

O Problema da Configuração Manual

Para um computador entrar na rede, ele precisa de 4 informações essenciais:

Endereço IP Máscara Gateway Servidor DNS
Se você tiver uma rede corporativa com 500 computadores e celulares, colocar isso à mão num por num resultará em caos (IPs duplicados = Conflito de IP).

O DHCP foi criado para entregar todos estes dados automaticamente em milissegundos assim que você conecta o cabo ou liga o Wi-Fi.

DHCP na Camada de Transporte

O DHCP usa UDP porque precisa ser super leve e usar mensagens do tipo Broadcast (enviar para todos ao mesmo tempo), o que o TCP não suporta.

Porta 67

Servidor DHCP

É a porta que o Router/Servidor fica "escutando", à espera que alguém peça um IP.

Porta 68

Cliente DHCP

É a porta que o seu celular/PC usa para enviar o pedido inicial.

O Famoso Processo D.O.R.A.

A negociação de um IP ocorre em 4 passos rápidos.

1. D - Discover

Cliente grita (Broadcast): "Alguém aqui é DHCP? Preciso de um IP!"

2. O - Offer

Servidor responde: "Eu sou! Posso emprestar o IP 192.168.1.50."

3. R - Request

Cliente confirma: "Beleza, eu aceito o IP 192.168.1.50!"

4. A - Acknowledge

Servidor finaliza: "Ok, registrado na minha tabela. Pode usá-lo."

Escopo e "Lease Time" (Tempo de Concessão)

O Escopo (Pool)

É a "caixa" de IPs que o Servidor tem para distribuir. Por exemplo, do 192.168.1.100 ao 192.168.1.200. O servidor nunca distribui o seu próprio IP (Gateway).

Lease Time (Aluguel)

O DHCP não "dá" um IP para sempre, ele aluga. Quando chega a 50% do tempo de aluguel, o cliente tenta Renovar automaticamente em silêncio.

E se eu precisar de um IP Fixo?

Impressoras e Servidores não devem mudar de IP, senão os usuários perdem o acesso a eles. Temos duas opções:

A
IP Estático Manual: Configuramos no próprio equipamento, mas fora do "Pool" do DHCP para evitar conflitos.
B
Reserva DHCP (Recomendado): Vamos ao Servidor DHCP e configuramos: "O equipamento com o Endereço MAC AA:BB:CC recebe sempre o IP .20". É automático, mas centralizado!

Troubleshooting L7: DNS

Como investigar se o problema é o DNS quando a internet "cai"?

C:\> ping 8.8.8.8
Resposta de 8.8.8.8: bytes=32 tempo=12ms TTL=117

C:\> ping google.com
A solicitação ping não pôde encontrar o host google.com.
Diagnóstico: Se você pinga um IP (8.8.8.8) com sucesso, mas não consegue pingar um nome, a sua internet está a funcionar, mas o seu Servidor DNS falhou!

Troubleshooting L7: DHCP

A máquina Windows perdeu o IP e ficou com um bizarro `169.254.x.x` (APIPA)? Forçar a renovação!

1. Liberar o atual

ipconfig /release

Envia uma mensagem ao servidor a dizer "Já não quero este IP". Fica a 0.0.0.0.

2. Pedir um novo

ipconfig /renew

Força o processo DORA completo novamente do zero.

A ferramenta: nslookup

O nslookup (Name Server Lookup) é a melhor ferramenta para consultar manualmente os registros do DNS e testar os servidores.

C:\> nslookup facebook.com
Servidor: dns.google
Address: 8.8.8.8

Não é resposta autoritativa:
Nome: facebook.com

Resumo da Aula

1
DNS (UDP 53): Resolve nomes em IPs. O processo é Recursivo no seu ISP, e Iterativo entre os servidores raiz/TLD na internet.
2
Registros DNS: A (IPv4), AAAA (IPv6), CNAME (Apelido/Alias), MX (Servidor de E-mail).
3
DHCP (UDP 67/68): Entrega Configuração de rede. Opera via processo D.O.R.A. e baseia-se em Aluguel (Lease Time).
4
Troubleshooting: O comando ipconfig /renew resolve falhas DHCP e o nslookup diagnostica problemas DNS.
"DNS e DHCP são os heróis invisíveis. Sem eles, a internet dependeria de um caderno de apontamentos cheio de números e reconfigurações diárias na placa de rede."
