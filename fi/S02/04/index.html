Personal Access Token (Classic)

Slide 03

O Que É um Token de Acesso?

Na Aula 3 vocês usaram uma chave SSH pra se autenticar no GitHub. Hoje existe uma segunda forma: o Personal Access Token (Classic). O GitHub não aceita mais a senha normal da sua conta pra operações git via HTTPS — então, ou você usa uma chave SSH (Aula 3), ou usa um token no lugar da senha. É tipo entrar numa festa: sem o crachá certo, nem adianta tentar na porta.

Definição formal

Um Personal Access Token é um código gerado pelo próprio GitHub que funciona como uma senha especial — usado só quando você conecta ao GitHub via HTTPS (em vez de SSH) pra operações como git push.

Slide 04

Como Gerar seu Token (Classic)

  1. No GitHub: clique na sua foto de perfil → Settings
  2. Developer settings → Personal access tokens → Tokens (classic)
  3. Generate new token (classic)
  4. Marque o escopo repo e defina uma validade
  5. Clique em Generate token
  6. Copie o token na hora — ele só aparece uma vez!

Atenção

Se fechar a página sem copiar, não tem como recuperar o token — só gerando um novo. Cole ele num lugar seguro antes de continuar.

Slide 05

Como Usar o Token

Quando você conecta a um repositório pela URL HTTPS (não SSH) e roda git push, o Git pede usuário e senha. No campo de senha, é o token que entra — não a senha real da sua conta.

$ git push origin main
Username for 'https://github.com': seu-usuario
Password for 'https://seu-usuario@github.com': [cole o token aqui]
Slide 06

SSH vs Token Classic — Qual Escolher?

Comparativo rápido
CritérioSSH (chave)Token Classic
Configuração inicialMais passos (gerar par de chaves, cadastrar no GitHub)Mais rápido de gerar
Uso no dia a diaConfigura uma vez, nunca mais pede nadaPrecisa colar de novo de tempos em tempos, a não ser que o Git guarde em cache
Se aplica melhor quando...Já configurou na Aula 3Ainda não tem chave e quer algo rápido hoje

Escolha só UM dos dois

Pra hoje, use SSH (se já configurou na Aula 3) OU gere um Token Classic (novo). Não precisa fazer os dois.

Exercício — Parte 1

Repositório local com histórico de verdade

Slide 07

Passo 1: Criando o Repositório e o Primeiro Programa

  1. Crie uma pasta nova e entre nela (ex: mkdir exercicio-consolidacao && cd exercicio-consolidacao)
  2. Rode git init
  3. Crie o arquivo bissexto.c com o código abaixo
bissexto.c
#include <stdio.h>

int main() {
    int ano;

    printf("Digite um ano: ");
    scanf("%d", &ano);

    if ((ano % 4 == 0 && ano % 100 != 0) || ano % 400 == 0) {
        printf("%d é bissexto!\n", ano);
    } else {
        printf("%d não é bissexto.\n", ano);
    }

    return 0;
}
Slide 08

Passo 2: Primeiro Commit

Lembra da Aula 1: cada commit é um ponto marcado na linha do tempo do projeto. Vamos marcar o primeiro.

git add bissexto.c
git commit -m "Adiciona verificador de ano bissexto"
Slide 09

Passo 3: Segundo Programa — Calculadora de IMC

Agora crie, na mesma pasta, o arquivo imc.c: lê peso e altura, calcula o IMC (peso ÷ altura²) e imprime a classificação.

imc.c
#include <stdio.h>

int main() {
    float peso, altura, imc;

    printf("Digite seu peso (kg): ");
    scanf("%f", &peso);

    printf("Digite sua altura (m): ");
    scanf("%f", &altura);

    imc = peso / (altura * altura);

    printf("Seu IMC é: %.2f\n", imc);

    if (imc < 18.5)
        printf("Classificação: abaixo do peso\n");
    else if (imc < 25.0)
        printf("Classificação: peso normal\n");
    else if (imc < 30.0)
        printf("Classificação: sobrepeso\n");
    else
        printf("Classificação: obesidade\n");

    return 0;
}
Slide 10

Passo 4: Segundo Commit

git add imc.c
git commit -m "Adiciona calculadora de IMC"
Slide 11

Passo 5: Uma Melhoria e o Terceiro Commit

Commits pequenos e frequentes contam a história do projeto — é assim que se farma um histórico de verdade. Escolha UMA melhoria em um dos programas, por exemplo: validar ano negativo no bissexto.c.

bissexto.c (trecho novo)
if (ano <= 0) {
    printf("Ano inválido!\n");
    return 1;
}
git add bissexto.c
git commit -m "Valida entrada de ano negativo no bissexto.c"
Slide 12

Passo 6: Conferindo o Histórico

Rode git log --oneline e confira: precisam aparecer os 3 commits, na ordem certa.

$ git log --oneline
c3d4e5f Valida entrada de ano negativo no bissexto.c
b2c3d4e Adiciona calculadora de IMC
a1b2c3d Adiciona verificador de ano bissexto

Exercício — Parte 2

Autenticação e push pro GitHub

Slide 13

Passo 1: Escolher o Método e Criar o Repositório

  1. Escolha: SSH (se já tem chave da Aula 3) ou Token Classic (gerado agora)
  2. No GitHub, clique em New repository
  3. Dê um nome (ex: exercicio-consolidacao)
  4. NÃO marque "Add a README file" — o repositório precisa nascer vazio
  5. Clique em Create repository
Slide 14

Passo 2: Conectando o Repositório

Copie a URL do repositório vazio que o GitHub mostrou — SSH ou HTTPS, dependendo do método escolhido — e conecte:

# se estiver usando SSH (Aula 3)
git remote add origin git@github.com:seu-usuario/exercicio-consolidacao.git

# se estiver usando Token Classic (HTTPS)
git remote add origin https://github.com/seu-usuario/exercicio-consolidacao.git
Slide 15

Passo 3: Push e Conferência

git push -u origin main
# Se usou Token Classic, o Git vai pedir usuário e senha —
# cole o token no campo de senha

Confira no site

Abra o repositório no navegador e confirme que os 3 commits aparecem, com as mensagens certas, no histórico.
