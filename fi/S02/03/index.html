Slide 02

Git ≠ GitHub

O Git que vocês usam desde a Aula 1 roda 100% no seu computador — cada commit fica guardado só ali. O GitHub é outra coisa: um serviço na internet que hospeda uma cópia do seu repositório na nuvem.

Git

  • Ferramenta
  • Roda local, no seu PC
  • Você já usa desde a Aula 1
  • Funciona até sem internet

GitHub

  • Serviço (site)
  • Guarda uma cópia remota
  • Assunto de hoje
  • Precisa de internet

Existem outras opções

GitLab e Bitbucket fazem algo parecido — mas o foco da disciplina (e do mercado) é o GitHub.

Slide 03

# Conecta o repo local a um endereco remoto, apelidado de "origin"
git remote add origin <url-do-repositorio>

# Confirma que a conexao foi criada
git remote -v

origin é só um apelido — poderia ser outro nome, mas por convenção todo mundo chama assim.

Login e senha? Não mais.

GitHub não aceita mais senha simples por HTTPS — hora de conhecer o SSH

Slide 04

Chave pública e chave privada

Pensa num cadeado: a chave privada é a chave física, que só você tem — nunca sai do seu bolso. A chave pública é o próprio cadeado — você pode distribuir quantas cópias quiser, só quem tem a chave privada consegue abrir.

Chave privada

Fica só no seu computador. NUNCA compartilhe com ninguém.

Chave pública

Vai pro GitHub. Pode compartilhar à vontade.

Na prática

Quando você faz um push, o GitHub desafia seu computador a provar que tem a chave privada certa — sem digitar senha nenhuma.

Slide 05

Gerando sua chave SSH

# Gera um novo par de chaves (algoritmo ed25519)
ssh-keygen -t ed25519 -C "seuemail@exemplo.com"

# As chaves ficam salvas em:
# ~/.ssh/id_ed25519      -> privada (NUNCA compartilhe)
# ~/.ssh/id_ed25519.pub  -> publica (essa vai pro GitHub)
  1. Copie a chave pública: cat ~/.ssh/id_ed25519.pub
  2. No GitHub: Settings → SSH and GPG keys → New SSH key → cole
  3. Teste a conexão: ssh -T git@github.com
Slide 06

Criando o repositório no GitHub

  1. No GitHub, clique em New repository
  2. Dê um nome, ex: portfolio-pessoal
  3. NÃO marque "Add a README" — o remoto nasceria com um commit que o seu local não tem
  4. Copie a URL SSH: git@github.com:seu-usuario/portfolio-pessoal.git
git remote add origin git@github.com:seu-usuario/portfolio-pessoal.git

# Confirma a conexao
git remote -v

Hora de subir a linha do tempo

git push: enviando seus commits pro GitHub

Slide 07

git push

# Primeira vez: envia e memoriza a ligacao origin/main
git push -u origin main

# Da segunda vez em diante, so:
git push

O -u (de --set-upstream) diz: "lembra dessa combinação origin/main pras próximas vezes" — depois disso, git push sozinho já sabe pra onde ir.

Pensa assim

É tipo salvar seu progresso na nuvem num jogo: se o PC bugar, sua aura de dev tá segura no GitHub.

E pra trazer de volta?

git pull atualiza o que já existe, git clone traz um repo do zero

Slide 10

Erros clássicos (e como resolver)

Permission denied (publickey)

Chave SSH não configurada. Confira com ssh -T git@github.com

fatal: not a git repository

Esqueceu o git init — confirme que está na pasta certa

failed to push some refs

O remoto tem commits que você não tem — rode git pull antes do push

Desafios

Mão na massa — Parte 1: dois programas em C

Vamos revisar TODO o ciclo do Git desde a Aula 1 — init, status, diff, add, commit, log — antes de subir pro GitHub.

  1. Crie uma pasta nova (ex: exercicios-c), entre nela e rode git init pra começar um repositório do zero
  2. Escreva um programa em C chamado par_impar.c: lê um número inteiro digitado pelo usuário e imprime se ele é par ou ímpar
  3. Confira com git status o que está pronto pra ser versionado, adicione com git add par_impar.c e faça o primeiro commit com uma mensagem clara
  4. Escreva um segundo programa, media_notas.c: lê três notas e calcula a média, imprimindo se o aluno foi aprovado (média ≥ 6) ou reprovado
  5. Repita o ciclo pro segundo programa: git status, git add media_notas.c, git commit
  6. Rode git log --oneline e confira os dois commits na sua linha do tempo
Desafios

Mão na massa — Parte 2: subindo pro GitHub

  1. Se ainda não tiver, gere sua chave SSH com ssh-keygen -t ed25519 e cadastre a pública no GitHub (Settings → SSH and GPG keys)
  2. Crie um repositório vazio no GitHub chamado exercicios-c (sem README)
  3. Conecte com git remote add origin <url-ssh> e confirme com git remote -v
  4. Suba tudo com git push -u origin main
  5. Confira no site do GitHub: os dois arquivos .c e os dois commits devem aparecer no histórico

Se der erro, tranquilo

Permission denied ou failed to push são exatamente os erros clássicos de alguns slides atrás — consulta ali e resolve com calma.
