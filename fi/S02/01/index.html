Slide 04

Git é uma Linha do Tempo

Todo projeto guardado no Git tem uma linha do tempo própria. Cada vez que você marca um ponto nela, o Git tira uma fotografia completa do projeto naquele instante — e você pode visitar qualquer um desses pontos depois, quando quiser, como um viajante do tempo revisitando o passado.

A linha do tempo do projeto
flowchart LR subgraph SG1["Commit 1"] direction TB A1["Início do projeto"] end subgraph SG2["Commit 2"] direction TB A2["Cria interface da máquina do tempo"] end subgraph SG3["Commit 3"] direction TB A3["Ajusta o motor do tempo"] end subgraph SG4["Commit 4 (estável)"] direction TB A4["Corrige bug de paradoxo"] end subgraph SG5["Commit 5"] direction TB A5["Adiciona pouso suave na chegada"] end SG1 --> SG2 --> SG3 --> SG4 --> SG5
Cada coluna é um ponto marcado — chamado de commit. Vamos entender exatamente o que isso significa a seguir.

Commit: Marcando um Ponto na Linha do Tempo

O conceito central do Git

Slide 05

O Que é um Commit? (Parte 1)

Pensa numa fotografia

Um commit é uma foto completa do seu projeto, tirada num instante exato. Diferente de uma foto comum, essa aqui guarda tudo que é preciso pra reconstruir o projeto exatamente como ele estava naquele momento.

Cada commit vira um ponto marcado, fixo, na linha do tempo. Depois de marcado, ele não desaparece — você pode visitá-lo de novo quando quiser, mesmo que o projeto já tenha mudado muito desde então.

Slide 06

O Que é um Commit? (Parte 2)

git commit -m "corrige bug do motor do tempo"
Um novo ponto entra na linha do tempo
flowchart LR subgraph SG1["Commit 1"] direction TB A1["Início do projeto"] end subgraph SG2["Commit 2"] direction TB A2["Cria interface da máquina do tempo"] end subgraph SG3["Commit 3"] direction TB A3["Ajusta o motor do tempo"] end subgraph SG4["Commit 4 (novo!)"] direction TB A4["Corrige bug do motor do tempo"] end SG1 --> SG2 --> SG3 --> SG4
Cada git commit adiciona uma nova coluna na linha do tempo, sempre depois da última — aqui, o commit mais novo ainda leva a etiqueta "novo!".

Rótulo do Commit: a Mensagem

Pra não se perder na própria linha do tempo

Slide 07

Todo Ponto Marcado Leva um Rótulo

Por que rotular?

Sem uma mensagem clara, um commit é só uma coluna sem nome no meio da linha do tempo. O rótulo (a mensagem de commit) é o que permite entender, meses depois, o que foi feito ali e por quê.

Rótulo ruim vs. rótulo bom
Mensagem ruimMensagem boa
"mudancas""Corrige cálculo de datas na viagem"
"fix""Adiciona validação de input do usuário"
"asdsad""Remove log de debug esquecido"

Viajando na Linha do Tempo

Voltar num ponto e trazer pro presente

Slide 08

Voltar, Pegar e Trazer pro Presente

A intuição por trás disso

Como cada commit guarda uma foto completa do projeto, você pode voltar em qualquer ponto antigo da linha do tempo, pegar o que estava lá, e trazer de volta pro presente — podendo editar aquilo ou manter exatamente como estava.

Isso é uma das partes mais poderosas do Git. Os comandos pra fazer essa viagem de verdade (git checkout, git revert, entre outros) a gente destrincha com calma mais pra frente no nosso módulo de Git — por hoje, o que importa é essa intuição: nada que virou commit se perde de verdade.

Git Add: o Diário do Tempo

Antes de marcar o ponto, você anota o que entra nele

Slide 09

Git Add: o Diário do Tempo (Parte 1)

O diário antes da marca

Antes de marcar um ponto na linha do tempo, você decide o que vai entrar nele. É como escrever num diário de bordo: só o que você anota (com git add) é o que o commit vai guardar. Sem isso, o commit não sabe o que salvar.

Editando

Arquivo modificado, mudança ainda solta

git add

Mudança anotada no diário, pronta pra virar commit

git commit

Ponto marcado, definitivo, na linha do tempo

Slide 10

O Fluxo Básico do Dia a Dia (Parte 2)

Do arquivo editado ao ponto marcado
flowchart LR A[Edita o arquivo] --> B[git add] B --> C[git commit -m] C --> D[Novo ponto na linha do tempo]
Esse ciclo se repete o tempo todo: editar, anotar no diário, marcar o ponto.
git add maquina_do_tempo.py
git commit -m "Corrige calculo de datas na viagem"

Consistência > commit gigante

Assim como quem quer farmar aura de verdade sabe que é repetição pequena e constante que funciona, aqui vale o mesmo: commits pequenos e frequentes valem muito mais que um commit gigante e raro no fim do dia.

Git Status: Onde Você Está Agora

Consultando o mapa da linha do tempo

Slide 11

git status: a Bússola do Git (Parte 1)

$ git status
On branch main
Changes not staged for commit:
  modified:   maquina_do_tempo.py

Untracked files:
  novo_registro.txt

Pra que serve

git status mostra onde você está agora: o que foi modificado mas ainda não entrou no diário (not staged), o que já está anotado pronto pro commit, e o que o Git ainda nem conhece (untracked).

Slide 12

git status: a Bússola do Git (Parte 2)

Os três estados de um arquivo
flowchart LR U["Untracked<br/>novo_registro.txt"] -->|git add| S["Staged<br/>no diário"] M["Modified, not staged<br/>maquina_do_tempo.py"] -->|git add| S S -->|git commit| C["Committed<br/>ponto marcado"]
O git status que você acabou de ver é exatamente uma foto desses estados: ele te diz em qual dessas caixinhas cada arquivo do projeto está agora.

Repare que nada vira commit sem passar pelo git add primeiro — é essa etapa do meio (o "diário do tempo" que vimos antes) que decide o que vai ser marcado na linha do tempo.

Git Log: Vendo a Linha do Tempo Inteira

Todos os pontos marcados, até agora

Slide 13

git log: Onde Você Está Agora (Parte 1)

A linha do tempo até agora
flowchart LR subgraph SG1["1f0d4aa"] direction TB A1["Primeira versão da máquina do tempo"] end subgraph SG2["7b2e881"] direction TB A2["Adiciona validação de input do usuário"] end subgraph SG3["a3f9c21 (você está aqui)"] direction TB A3["Corrige cálculo de datas na viagem"] end SG1 --> SG2 --> SG3
Antes de rodar git log, pensa assim: você está sempre no ponto mais recente da sua linha do tempo. git log é o comando que revela todos os pontos anteriores a esse.

Repara nos identificadores (1f0d4aa, 7b2e881, a3f9c21) — são os mesmos códigos que você vai ver na tela a seguir, quando rodarmos git log de verdade.

Slide 14

git log: o Histórico Completo (Parte 2)

$ git log --oneline
a3f9c21 Corrige calculo de datas na viagem
7b2e881 Adiciona validacao de input do usuario
1f0d4aa Primeira versao da maquina do tempo

Literalmente a linha do tempo

git log mostra todos os commits já feitos, do mais recente pro mais antigo, cada um com seu identificador único (aquele código tipo a3f9c21) e o rótulo que você escreveu. É a linha do tempo inteira, na tela.

Slide 15

Prévia: Mais Ferramentas da Linha do Tempo

git diff

Compara dois pontos da linha do tempo e mostra exatamente o que mudou entre eles, linha por linha.

git branch

Cria uma linha do tempo paralela — um assunto grande demais pra hoje, que vira aula própria (Aula 4: Branches e Merges).

Não precisa decorar esses dois agora — é só pra você saber que eles existem e onde se encaixam na analogia.

Onde Baixar o Git (Pra Casa)

Nos laboratórios, ele já vem pronto

Slide 16

Quer o Git no Seu Computador?

Nos laboratórios da escola o Git já vem instalado, e todo o nosso trabalho vai ser sempre pelo terminal — não precisa instalar nada por aqui.

Pra usar em casa

Se você quiser ter o Git no seu próprio computador, baixe o instalador oficial em git-scm.com e siga o assistente de instalação — funciona pra Windows, macOS e Linux. Sem mistério, sem pegadinha.

Simulação: O Cliente Se Arrependeu

Descobrindo qual ponto da linha do tempo tem o que você precisa

Slide 17

O Pedido do Cliente (Parte 1)

O que aconteceu

O viajante vem construindo o site de um cliente. Semana passada, o cliente pediu um novo layout — e ele entregou, commit por commit. Hoje o cliente voltou atrás: "pensando bem... eu gostava mais de como estava antes."

Antes de sair mexendo em qualquer coisa...

Ele não lembra de cabeça qual ponto exato da linha do tempo tinha o site "do jeito antigo". Mas não precisa confiar na memória — a própria linha do tempo do projeto está ali pra consultar.

Slide 18

Passo 1: Onde Estamos Agora? (Parte 2)

$ git status
On branch main
nothing to commit, working tree clean

Por que checar isso primeiro

git status limpo confirma que não tem nada solto — nenhuma edição pendurada, nada fora do lugar. Tudo que já existe está seguro, marcado em algum ponto da linha do tempo. Só falta achar o ponto certo.

Slide 19

Passo 2: Vasculhando a Linha do Tempo (Parte 3)

$ git log --oneline

4de2210 Corrige responsividade no celular
c02f7e4 Ajusta cores do cabecalho
9a1e5b0 Primeira entrega do site pro cliente
Onde está o "jeito antigo" que o cliente quer
flowchart LR subgraph SG1["9a1e5b0"] direction TB A1["Primeira entrega do site"] end subgraph SG2["c02f7e4"] direction TB A2["Ajusta cores do cabeçalho"] end subgraph SG3["4de2210 (o que o cliente quer)"] direction TB A3["Corrige responsividade no celular"] end subgraph SG4["d48ac31"] direction TB A4["Aplica novo layout pedido"] end SG1 --> SG2 --> SG3 --> SG4
Pelos rótulos, 4de2210 é o último ponto antes do novo layout entrar — o candidato mais forte pro que o cliente descreveu.

Achamos um candidato só de ler os rótulos. Mas dá pra confirmar o que exatamente esse commit continha, sem mexer em nada ainda? É pra isso que serve o próximo comando.

Slide 20

Passo 3: Espiando com git show (Parte 4)

git show: só espiar, nada de mexer

git show deixa você ver o conteúdo de um commit específico — o que mudou ali, quem fez, quando — sem trazer nada de volta pro presente. É só uma espiada na linha do tempo.

$ git show 4de2210
commit 4de2210f8a3b5c9e1d2f4a6b8c0d2e4f6a8b0c2d
Author: Viajante <viajante@maquinadotempo.dev>
Date:   Wed Jul 15 14:32:00 2026

    Corrige responsividade no celular

diff --git a/estilo.css b/estilo.css
- .menu { display: none; }
+ .menu { display: flex; flex-wrap: wrap; }
Slide 21

Confirmado! E Agora? (Parte 5)

Achamos o ponto certo

O git show confirmou: o commit 4de2210 tem exatamente o estado do site antes do novo layout — o que o cliente queria de volta. Sem adivinhar, sem depender de memória: a linha do tempo (e os comandos certos) resolveram sozinhos.

Próximo passo (spoiler)

Trazer esse ponto de volta pro presente é o passo seguinte — os comandos pra isso (git checkout, git restore) a gente destrincha com calma em breve, como já avisamos lá atrás. Por hoje, o que importa é: você sabe exatamente onde, na linha do tempo, está o que precisa.

Praticando

Mão no terminal do laboratório

Desafios

Praticando com o Git

  1. Abra o terminal num projeto com Git já iniciado e rode git status. O que ele te mostra sobre o momento atual da linha do tempo?
  2. Crie ou edite um arquivo, rode git add nomedoarquivo e confirme com git status que ele virou parte do 'diário' (staged).
  3. Faça seu primeiro commit com uma mensagem clara: git commit -m "minha primeira marca na linha do tempo".
  4. Rode git log e identifique: quantos commits existem, qual é o mais recente, e o que cada rótulo te conta sobre a história do projeto.
  5. Reflexão: qual seria aquele momento do seu passado (num trabalho, projeto ou código) que você mais gostaria de poder 'visitar' de novo com o Git?
