Slide 03

O que é o Create?

Pensa num jogo online: quando você cria um personagem novo, ele não existia antes — a partir daquele momento ele passa a existir no servidor. Create é exatamente isso pro banco de dados: pegar dados que não existiam numa tabela e fazer eles passarem a existir, como uma linha nova.

Definição formal

Create = inserir uma linha nova numa tabela do banco (INSERT INTO), a partir de dados que o usuário forneceu na interface (formulário).

Slide 05

Criando o preload.js

Vamos criar um arquivo novo, src/main/preload.js — a mesma ideia da Aula 1, expondo uma função que segue o padrão invoke.

src/main/preload.js
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('api', {
  criarInsumo: (insumo) => ipcRenderer.invoke('insumo:criar', insumo)
});

Por Que Não Existia Ainda

A Aula 1 só pediu o esqueleto visual do projeto — sem persistência. Por padrão, o Electron isola completamente o Renderer do Node.js (contextIsolation); sem um preload.js ligado à janela, window.api simplesmente não existe.

Slide 06

Ligando o preload à Janela do Insumo

Ter o arquivo não basta — o main.js precisa dizer pra janela do formulário usar esse preload.js, através de webPreferences. Aproveite também pra importar o ipcMain, que ainda não estava sendo usado.

src/main/main.js
const { app, BrowserWindow, Menu, Tray, dialog, ipcMain } = require('electron');
const path = require('path');
const conexao = require('./conexao');

const abrirModalInsumo = (janelaPrincipal) => {
    const janelaModal = new BrowserWindow({
        width: 400, height: 550,
        parent: janelaPrincipal, modal: true,
        webPreferences: {
            preload: path.join(__dirname, 'preload.js')
        }
    });
    janelaModal.removeMenu();
    janelaModal.loadFile(path.join(__dirname, '../renderer/frmInsumo.html'));
};

Slide 07

main.js: o INSERT de Verdade

Com ipcMain importado e a conexao já disponível, é só registrar o handler que faz o INSERT de verdade na tabela insumo.

src/main/main.js
ipcMain.handle('insumo:criar', (evento, insumo) => {
  return new Promise((resolve, reject) => {
    const sql = 'INSERT INTO insumo (tipo, nome, valor, data_aquisicao) VALUES (?, ?, ?, ?)';

    conexao.query(sql, [insumo.tipo, insumo.nome, insumo.valor, insumo.data_aquisicao], (erro, resultado) => {
      if (erro) {
        reject(erro);
        return;
      }
      resolve({ id: resultado.insertId, ...insumo });
    });
  });
});

Onde Colocar

Pode declarar esse ipcMain.handle em qualquer lugar do main.js, desde que fora de outra função — um bom lugar é logo abaixo de criarTray, antes do fechamento do arquivo.

Slide 08

Anatomia da Query: o SQL e os ?

Antes de seguir, vale destrinchar esse handler linha a linha. Primeiro, a string SQL em si.

const sql = 'INSERT INTO insumo (tipo, nome, valor, data_aquisicao) VALUES (?, ?, ?, ?)';
Cada ? tem uma posição fixa
PosiçãoColuna (na lista após INSERT INTO)? correspondente
1ªtipo1º ?
2ªnome2º ?
3ªvalor3º ?
4ªdata_aquisicao4º ?
A ordem das colunas entre parênteses define a ordem que os ? vão ser preenchidos — não é por nome, é por posição.

Por que ? em vez do valor direto?

Cada ? é um placeholder: na hora de executar, o driver mysql2 substitui cada um pelo valor certo do array de forma seguro — o valor nunca é "colado" como texto dentro do comando SQL (é assim que evitamos SQL Injection, como já vimos).

Slide 09

conexao.query: os Três Argumentos

conexao.query(...) é o método do driver mysql2 que realmente conversa com o MySQL. Ele sempre recebe os mesmos três argumentos.

conexao.query(
  sql,                                                              // 1. a query com os ?
  [insumo.tipo, insumo.nome, insumo.valor, insumo.data_aquisicao],  // 2. os valores, na mesma ordem
  (erro, resultado) => { /* 3. o callback, chamado quando o banco responde */ }
);

1º: o sql

A string com o comando e os ? no lugar dos valores.

2º: o array

Os valores reais, na MESMA ordem dos ? — posição 1 do array vai pro 1º ?, e assim por diante.

3º: o callback

Uma função (erro, resultado) chamada quando o MySQL termina de processar o INSERT.

A ordem do array importa

Se você trocar a ordem do array sem trocar a ordem das colunas no SQL, o INSERT não vai dar erro — ele só vai gravar cada valor na coluna errada, silenciosamente. Sempre confira se a ordem do array bate com a ordem das colunas.

Slide 10

resolve e reject: Aplicando a Aula 1

Lembra da entrega por aplicativo?

Na Aula 1, vimos que uma Promise nasce pendente e só termina de dois jeitos: resolve(...) ("entregue", deu certo) ou reject(...) ("cancelado", deu errado). É exatamente esse padrão que o handler de hoje usa.

return new Promise((resolve, reject) => {
  conexao.query(sql, [...], (erro, resultado) => {
    if (erro) {
      reject(erro);          // "cancelado": algo deu errado
      return;
    }
    resolve({ id: resultado.insertId, ...insumo }); // "entregue": sucesso
  });
});

O que é esse ...insumo?

É o spread operator que vocês já viram lá no começo da disciplina — ...insumo "espalha" todas as propriedades do objeto insumo (tipo, nome, valor, data_aquisicao) dentro do objeto novo. Ou seja, { id: resultado.insertId, ...insumo } monta um objeto único com o id que o banco acabou de gerar mais todos os campos que já tínhamos, sem precisar listar cada um na mão.

Por que envolver tudo num new Promise?

conexao.query usa o formato antigo de callback do Node.js, que não é "aguardável" com await. Envolvendo ele num new Promise, a gente traduz esse callback pra uma Promise de verdade — é isso que permite o frmInsumo.js fazer await window.api.criarInsumo(dados) mais adiante. resultado.insertId é o id gerado automaticamente pro insumo novo, devolvido junto no resolve.

Slide 11

Segurança: Nunca Concatene Valores!

// ❌ NUNCA FAÇA ISSO — concatenar valor direto na query
const sql = `INSERT INTO insumo (tipo, nome, valor, data_aquisicao)
             VALUES ('${insumo.tipo}', '${insumo.nome}', ${insumo.valor}, '${insumo.data_aquisicao}')`;
conexao.query(sql, (erro, resultado) => { /* ... */ });

// ✅ Faça assim — "?" é um placeholder, os valores vão num array separado
const sql = 'INSERT INTO insumo (tipo, nome, valor, data_aquisicao) VALUES (?, ?, ?, ?)';
conexao.query(sql, [insumo.tipo, insumo.nome, insumo.valor, insumo.data_aquisicao], (erro, resultado) => { /* ... */ });

Por Que Isso Importa: SQL Injection

Se o valor do usuário vira texto direto dentro da query, alguém pode digitar no formulário um texto que muda o comando SQL de verdade (ex: fechar as aspas e colar outro comando). O driver mysql2 trata o ? como um valor puro, nunca como parte do comando — por isso ele é sempre a forma segura de montar a query.

Slide 12

frmInsumo.js: Chamando a API de Verdade

Voltando pro Renderer: o TODO do frmInsumo.js finalmente vira código de verdade. O resto do arquivo (capturar com FormData) já estava pronto desde a Aula 1.

src/renderer/js/frmInsumo.js
document.querySelector("#formInsumo").addEventListener("submit", async (e) => {
    e.preventDefault(); // Evita o piscar da tela

    const dados = Object.fromEntries(new FormData(e.target));
    dados.valor = Number(dados.valor);

    try {
        const resultado = await window.api.criarInsumo(dados);
        console.log("Insumo cadastrado:", resultado);
        e.target.reset(); // limpa o formulario pro proximo cadastro
    } catch (erro) {
        console.error("Deu ruim ao cadastrar o insumo:", erro);
        alert("Nao foi possivel cadastrar o insumo.");
    }
});

Só Isso Mudou

Onde tinha só um console.log de TODO, agora entra a chamada real: window.api.criarInsumo(dados) — exatamente a função que o preload.js expôs.

O Padrão que Você Vai Usar Sempre

preload expõe -> webPreferences liga -> handle recebe -> INSERT com ? -> resolve -> Renderer trata sucesso/erro. Todo Create da disciplina segue esse mesmo caminho — inclusive o de Peça Impressa, no exercício de hoje.
