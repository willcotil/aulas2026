Slide 03

O que é o Create?

Pensa num jogo online: quando você cria um personagem novo, ele não existia antes — a partir daquele momento ele passa a existir no servidor. Create é exatamente isso pro banco de dados: pegar dados que não existiam numa tabela e fazer eles passarem a existir, como uma linha nova.

Definição formal

Create = inserir uma linha nova numa tabela do banco (INSERT INTO), a partir de dados que o usuário forneceu na interface (formulário).

Slide 06

Capturando os dados com FormData

Recap da Aula 11 do semestre passado: new FormData(form) lê o formulário inteiro de uma vez — a gente só precisa "traduzir" pra um objeto simples antes de mandar pro Main.

renderer.js
const formProduto = document.querySelector('#form-produto');

formProduto.addEventListener('submit', (evento) => {
  evento.preventDefault(); // impede o recarregamento da página

  const dados = new FormData(formProduto);

  const produto = {
    nome: dados.get('nome'),
    quantidade: Number(dados.get('quantidade'))
  };

  console.log(produto); // { nome: 'Poção de Aura +100', quantidade: 10 }
});
Slide 07

preload.js: expondo a função

Mesmo padrão da Aula 1: o preload.js é a única porta entre Renderer e Main. Aqui a gente abre uma porta nova, criarProduto, que já manda os dados junto no invoke.

preload.js
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('api', {
  criarProduto: (produto) => ipcRenderer.invoke('produto:criar', produto)
});
Slide 08

main.js: o INSERT de verdade

Quem faz a pergunta ao banco é quem precisa da resposta — por isso o INSERT mora aqui no main.js, não no database.js. A connection só é importada e reaproveitada.

main.js
const connection = require('./database.js');

ipcMain.handle('produto:criar', (evento, produto) => {
  return new Promise((resolve, reject) => {
    const sql = 'INSERT INTO produto (nome, quantidade) VALUES (?, ?)';

    connection.query(sql, [produto.nome, produto.quantidade], (erro, resultado) => {
      if (erro) {
        reject(erro);
        return;
      }
      resolve({ id: resultado.insertId, ...produto });
    });
  });
});
Slide 09

Segurança: nunca concatene valores!

// ❌ NUNCA FAÇA ISSO — concatenar valor direto na query
const sql = `INSERT INTO produto (nome, quantidade)
             VALUES ('${produto.nome}', ${produto.quantidade})`;
connection.query(sql, (erro, resultado) => { /* ... */ });

// ✅ Faça assim — "?" é um placeholder, os valores vão num array separado
const sql = 'INSERT INTO produto (nome, quantidade) VALUES (?, ?)';
connection.query(sql, [produto.nome, produto.quantidade], (erro, resultado) => { /* ... */ });

Por que isso importa: SQL Injection

Se o valor do usuário vira texto direto dentro da query, alguém pode digitar no formulário um texto que muda o comando SQL de verdade (ex: fechar as aspas e colar outro comando). O driver mysql2 trata o ? como um valor puro, nunca como parte do comando — por isso ele é sempre a forma segura de montar a query.

Slide 10

Testando na prática (Renderer)

Juntando tudo: capturar com FormData, chamar a função exposta pelo preload, e tratar sucesso (limpar o form) e erro (avisar o usuário) — igual toda Promise que já usamos.

renderer.js
formProduto.addEventListener('submit', async (evento) => {
  evento.preventDefault();

  const dados = new FormData(formProduto);
  const produto = {
    nome: dados.get('nome'),
    quantidade: Number(dados.get('quantidade'))
  };

  try {
    const resultado = await window.api.criarProduto(produto);
    console.log('Produto criado:', resultado);
    formProduto.reset(); // limpa o formulário pra já cadastrar o próximo
  } catch (erro) {
    console.error('Deu ruim ao criar o produto:', erro);
    alert('Não foi possível cadastrar o produto.');
  }
});

Resumo: o caminho completo do Create

Do clique no botão até a linha gravada no MySQL
sequenceDiagram participant U as Usuário participant R as Renderer participant P as preload.js participant M as main.js participant DB as MySQL U->>R: Preenche e envia o formulário R->>R: new FormData(form) R->>P: window.api.criarProduto(produto) P->>M: ipcRenderer.invoke("produto:criar") M->>DB: INSERT INTO produto VALUES (?, ?) DB-->>M: Linha criada (insertId) M-->>P: resolve(resultado) P-->>R: Promise resolvida R->>U: Mostra sucesso e limpa o form

O padrão que você vai usar sempre

Formulário -> FormData -> invoke -> handle -> INSERT (com ?) -> resolve -> feedback na tela. Todo Create da disciplina (inclusive no projeto real) segue esse mesmo caminho.

Desafios

Agora é sua vez: Create no Gerenciador de Peças 3D

Aplique exatamente o mesmo padrão do exemplo produto na tabela insumo (id, tipo, nome, valor, data_aquisicao) do projeto real.

  1. No preload.js, exponha uma função criarInsumo(insumo) que chama ipcRenderer.invoke('insumo:criar', insumo).
  2. No main.js, crie o ipcMain.handle('insumo:criar', ...) montando o INSERT INTO insumo (tipo, nome, valor, data_aquisicao) VALUES (?, ?, ?, ?) — reaproveitando a connection de database.js.
  3. No formulário de cadastro de insumo (já montado na Aula 1), capture os dados com FormData no submit e monte o objeto insumo.
  4. Chame window.api.criarInsumo(insumo): trate sucesso (limpe o formulário) e erro (mostre uma mensagem pro usuário).
  5. Teste inserindo pelo menos 3 insumos diferentes e confira no MySQL se as linhas foram gravadas certinho.

Terminou antes da turma?

Repita o mesmo padrão para a tabela pecaimpressa (titulo, cor, peso, quantidadematerial, tempoimpressao, dataimpressao). É prática extra — não é obrigatório fechar hoje.
