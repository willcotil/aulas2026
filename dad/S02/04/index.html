O Comando UPDATE e o WHERE

A cláusula que decide QUAIS linhas mudam

Slide 03

UPDATE: editando uma linha específica

SET muda os dados, WHERE escolhe a linha

Pensa no UPDATE como editar um contato no seu celular: você não cria um contato novo nem apaga o antigo — abre AQUELE contato específico e troca só o que mudou. O WHERE é exatamente isso: ele aponta pra LINHA certa da tabela. É a primeira vez que ele aparece na disciplina — SELECT e INSERT nunca precisaram dele.

UPDATE genérico
UPDATE insumo
SET tipo = ?, nome = ?, valor = ?, data_aquisicao = ?
WHERE id = ?;
Slide 04

O maior perigo do UPDATE

UPDATE sem WHERE = tragédia

Se você esquecer o WHERE, o comando não erra e não avisa nada — ele simplesmente aplica o SET em TODAS as linhas da tabela, de uma vez, sem pedir confirmação.

  • Isso já aconteceu (e continua acontecendo) até com quem programa há anos
  • Bancos de produção já foram zerados por um WHERE esquecido — erro clássico, não lenda urbana
  • Regra de ouro: escreva o WHERE ANTES de terminar de pensar no SET
comparação
-- CERTO — atualiza só o insumo escolhido
UPDATE insumo SET valor = ? WHERE id = ?;

-- ERRADO — sem WHERE, atualiza TODOS os insumos da tabela
UPDATE insumo SET valor = ?;

Slide 06

A coluna Ações ganha vida

De travessão a botão de verdade

Por que guardar insumosCarregados numa variável? Porque quando o botão Editar for clicado, só temos o id da linha — precisamos ir buscar o insumo completo em algum lugar, e esse lugar é essa variável.

frmPrincipal.js
let insumosCarregados = []; // guardamos a lista pra achar o insumo certo depois

const carregarInsumos = async () => {
  insumosCarregados = await window.api.listarInsumos();

  const linhas = insumosCarregados.map((insumo) => `
    <tr>
      <td>${insumo.tipo}</td>
      <td>${insumo.nome}</td>
      <td>${formatarMoeda(insumo.valor)}</td>
      <td>${formatarData(insumo.data_aquisicao)}</td>
      <td><button onclick="editarInsumo(${insumo.id})">Editar</button></td>
    </tr>
  `).join('');

  document.querySelector('#tbodyInsumos').innerHTML = linhas;
};

const editarInsumo = (id) => {
  const insumo = insumosCarregados.find((i) => i.id === id);
  window.api.editarInsumo(insumo);
};

IPC Novo: invoke/handle vs send/on

Nem toda comunicação espera resposta

Slide 07

Dois padrões de comunicação

Pergunta-resposta vs aviso de mão única

invoke / handle — Pergunta e Espera

O Renderer faz uma pergunta pro Main e FICA ESPERANDO a resposta (por isso o await). Já usamos em Create e Read, e vamos usar de novo pra salvar o Update.

  • invoke('insumo:criar')
  • invoke('insumo:listar')
  • invoke('insumo:atualizar')

send / on — Aviso, sem Resposta

O Main manda um aviso pro Renderer, tipo uma notificação — ninguém pediu, ninguém espera nada de volta. É assim que o modal de edição recebe os dados prontos pra preencher o formulário.

  • send('insumo:preencher', ...)
  • on('insumo:preencher', callback)
Slide 08

Comparando os dois padrões

invoke/handle vs send/on
sequenceDiagram participant R as Renderer participant P as Preload participant M as Main Note over R,M: Padrão 1 - invoke/handle (pergunta e espera resposta) R->>P: window.api.criarInsumo(dados) P->>M: ipcRenderer.invoke('insumo:criar', dados) M->>M: INSERT INTO insumo... M-->>P: resolve(resultado) P-->>R: return resultado Note over R,M: Padrão 2 - send/on (aviso de mao unica) M->>P: webContents.send('insumo:preencher', insumo) P->>R: ipcRenderer.on(...) dispara callback Note over R: Renderer recebe sem ter pedido nada
invoke/handle: pergunta e espera resposta. send/on: aviso de mão única, sem resposta.
Slide 09

O fluxo completo pra abrir a edição

  1. Usuário clica no botão Editar de uma linha da tabela
  2. frmPrincipal.js chama window.api.editarInsumo(insumo)
  3. Preload dispara ipcRenderer.invoke('insumo:abrirEdicao', insumo)
  4. main.js recebe no handle e chama abrirModalInsumo(janelaPrincipal, insumo)
  5. Quando a janela do modal termina de carregar (did-finish-load), o MAIN manda o insumo pro RENDERER com send
  6. frmInsumo.js estava escutando com on — recebe o insumo e preenche o formulário sozinho
Slide 10

main.js aprende a preencher o modal

abrirModalInsumo ganha um segundo parâmetro

src/main/main.js
const abrirModalInsumo = (janelaPai, insumo = null) => {
  const janelaModal = new BrowserWindow({
    width: 500,
    height: 600,
    parent: janelaPai,
    modal: true,
    webPreferences: {
      preload: path.join(__dirname, 'preload.js')
    }
  });

  janelaModal.loadFile('src/renderer/frmInsumo.html');

  // Só existe insumo quando estamos ABRINDO EM MODO EDIÇÃO
  if (insumo) {
    janelaModal.webContents.once('did-finish-load', () => {
      janelaModal.webContents.send('insumo:preencher', insumo);
    });
  }
};

// Chamado quando o usuário clica em "Editar" na tabela
ipcMain.handle('insumo:abrirEdicao', (evento, insumo) => {
  abrirModalInsumo(janelaPrincipal, insumo);
});

Slide 11

O handler do UPDATE

Mesma receita de sempre, com um novo ?

src/main/main.js
ipcMain.handle('insumo:atualizar', (evento, insumo) => {
  return new Promise((resolve, reject) => {
    const sql = 'UPDATE insumo SET tipo = ?, nome = ?, valor = ?, data_aquisicao = ? WHERE id = ?';
    const valores = [insumo.tipo, insumo.nome, insumo.valor, insumo.data_aquisicao, insumo.id];

    conexao.query(sql, valores, (erro, resultado) => {
      if (erro) {
        reject(erro);
      } else {
        resolve(resultado);
      }
    });
  });
});

Mesma receita de new Promise + conexao.query desde a Aula 2 — a única novidade é que o id também entra como ?, por último no array, na mesma ordem do WHERE id = ?. Nunca concatene o id direto na string — mesma regra de sempre.

Slide 12

preload.js completo

Repare qual padrão cada função usa

src/main/preload.js
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('api', {
  // já existiam (Aulas 2 e 3) — invoke/handle
  criarInsumo: (dados) => ipcRenderer.invoke('insumo:criar', dados),
  listarInsumos: () => ipcRenderer.invoke('insumo:listar'),

  // NOVO — invoke/handle: abre o modal já em modo edição
  editarInsumo: (insumo) => ipcRenderer.invoke('insumo:abrirEdicao', insumo),

  // NOVO — send/on: o main AVISA o formulário, sem que ele pergunte nada
  aoReceberInsumoParaEditar: (callback) =>
    ipcRenderer.on('insumo:preencher', (evento, insumo) => callback(insumo)),

  // NOVO — invoke/handle: salva a edição
  atualizarInsumo: (dados) => ipcRenderer.invoke('insumo:atualizar', dados)
});
Slide 13

frmInsumo.js completo

Recebe pra preencher, decide pra salvar

src/renderer/frmInsumo.js
let modoEdicao = false;
let idEmEdicao = null;

// Se o main mandar um insumo pra editar, preenche o formulário (send/on)
window.api.aoReceberInsumoParaEditar((insumo) => {
  document.querySelector('#tipo').value = insumo.tipo;
  document.querySelector('#nome').value = insumo.nome;
  document.querySelector('#valor').value = insumo.valor;
  document.querySelector('#data_aquisicao').value = insumo.data_aquisicao;

  modoEdicao = true;
  idEmEdicao = insumo.id;
});

document.querySelector('#formInsumo').addEventListener('submit', async (evento) => {
  evento.preventDefault();
  const dados = Object.fromEntries(new FormData(evento.target));

  if (modoEdicao) {
    await window.api.atualizarInsumo({ id: idEmEdicao, ...dados });
  } else {
    await window.api.criarInsumo(dados);
  }

  window.close(); // fecha o modal; frmPrincipal recarrega quando o foco voltar
});

Slide 14

O foco resolve a lista desatualizada

A ideia que a Aula 3 só cogitou, agora de verdade

A Aula 3 já tinha discutido esse problema: a lista da janela principal fica desatualizada enquanto outra janela mexe nos dados. A solução mais simples é essa — toda vez que a janela principal GANHA FOCO (por exemplo, quando o modal de edição fecha e o usuário volta pra ela), a gente recarrega a lista do zero.

src/renderer/frmPrincipal.js
// Recarrega a tabela sempre que a janela principal ganha foco
window.addEventListener('focus', carregarInsumos);
