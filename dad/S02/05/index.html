Slide 02

O botão Excluir

A coluna Ações da tabela em frmPrincipal.js já tem o botão Editar desde a Aula 4, dentro do mesmo carregarInsumos que já usamos desde a Aula 3. Hoje colocamos o irmão dele ao lado, na mesma célula: o botão Excluir.

frmPrincipal.js
// carregarInsumos ja existe desde a Aula 3/4 -- so adicionamos
// o botao Excluir do lado do Editar, na mesma celula de Acoes
const carregarInsumos = async () => {
  insumosCarregados = await window.api.listarInsumos();

  const linhas = insumosCarregados.map((insumo) => `
    <tr>
      <td>${insumo.tipo}</td>
      <td>${insumo.nome}</td>
      <td>${formatarMoeda(insumo.valor)}</td>
      <td>${formatarData(insumo.data_aquisicao)}</td>
      <td>
        <button onclick="editarInsumo(${insumo.id})">Editar</button>
        <button onclick="abrirConfirmacaoExclusao(${insumo.id})">Excluir</button>
      </td>
    </tr>
  `).join('');

  document.querySelector('#tbodyInsumos').innerHTML = linhas;
};

Mesmo truque do id

Os dois botões pegam o id do mesmo jeito: insumo.id, vindo do array insumosCarregados que a Aula 4 já guarda na memória para busca.

Por que nunca excluir direto no clique?

Delete é destrutivo e irreversível

Slide 03

Um clique não pode ser tudo que separa você de perder um dado

Já apagou sem querer uma conversa, uma foto ou o save de um jogo e ficou sem volta? Um botão Excluir que já dispara o DELETE no clique é exatamente isso — só que agora é o insumo de um cliente de verdade que some.

Delete não tem Ctrl+Z

Diferente de um erro de digitação, que dá pra corrigir com um novo Update, uma linha apagada do banco se foi de vez. Por isso toda exclusão precisa de uma confirmação explícita antes de disparar a query.

A solução: reaproveitar o modal do Bootstrap que já usamos desde o semestre 1 — só que agora com uma mensagem clara, tipo "Tem certeza que deseja excluir o insumo X? Essa ação não pode ser desfeita."

Slide 05

Por que a exclusão não precisa de send/on

Editar (Aula 4)

  • Precisa buscar o registro completo no banco
  • Usa insumo:abrirEdicao + send/on
  • O main.js devolve o insumo pro renderer

Excluir (hoje)

  • O id e o nome já estão no array insumosCarregados
  • Nenhuma viagem até o banco é necessária antes de abrir o modal
  • O JavaScript preenche o modal direto, via DOM
frmPrincipal.js
// Array `insumosCarregados` já existe desde a Aula 4 (busca por id)
let idParaExcluir = null;

const abrirConfirmacaoExclusao = (id) => {
  const insumo = insumosCarregados.find((item) => item.id === id);

  document.getElementById('nomeInsumoExcluir').textContent = insumo.nome;
  idParaExcluir = id;

  const modal = new bootstrap.Modal(
    document.getElementById('modalConfirmarExclusao')
  );
  modal.show();
};

Slide 06

A query do Delete

main.js
DELETE FROM insumo WHERE id = ?

O perigo do DELETE sem WHERE

DELETE FROM insumo; (sem WHERE) apaga TODAS as linhas da tabela de uma vez. Assim como no Update da Aula 4, o ? parametrizado garante que só a linha certa seja afetada — e evita SQL Injection.

Slide 07

O handler no main.js

main.js
ipcMain.handle('insumo:excluir', (evento, id) => {
  return new Promise((resolve, reject) => {
    const sql = 'DELETE FROM insumo WHERE id = ?';

    conexao.query(sql, [id], (erro, resultado) => {
      if (erro) {
        reject(erro);
        return;
      }
      resolve(resultado);
    });
  });
});

Mesmo padrão do Create/Read/Update: new Promise por fora, conexao.query por dentro, resolve no sucesso e reject no erro.

Slide 08

preload.js — expondo excluirInsumo

preload.js
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('api', {
  criarInsumo: (insumo) => ipcRenderer.invoke('insumo:criar', insumo),
  listarInsumos: () => ipcRenderer.invoke('insumo:listar'),
  editarInsumo: (insumo) => ipcRenderer.send('insumo:abrirEdicao', insumo),
  atualizarInsumo: (insumo) => ipcRenderer.invoke('insumo:atualizar', insumo),

  // NOVO -- invoke/handle: o frmPrincipal.js espera a exclusao terminar
  // antes de fechar o modal e recarregar a lista
  excluirInsumo: (id) => ipcRenderer.invoke('insumo:excluir', id),

  aoReceberInsumoParaEditar: (callback) =>
    ipcRenderer.on('insumo:preencher', (evento, insumo) => callback(insumo))
});

O mesmo objeto de sempre

É o mesmo api exposto desde a Aula 2 — só ganhou o excluirInsumo. Tudo o mais (editarInsumo via send, aoReceberInsumoParaEditar escutando insumo:preencher) continua exatamente como a Aula 4 deixou.

Slide 09

frmPrincipal.js — disparando a exclusão

frmPrincipal.js
document.getElementById('btnConfirmarExclusao')
  .addEventListener('click', async () => {
    await window.api.excluirInsumo(idParaExcluir);

    const modal = bootstrap.Modal.getInstance(
      document.getElementById('modalConfirmarExclusao')
    );
    modal.hide();

    carregarInsumos(); // mesma função da Aula 3
  });

Recarregar sempre

carregarInsumos() é a mesma função desde a Aula 3 — recarregar a lista depois de criar, editar OU excluir garante que a tela nunca fica desatualizada.

BD-->>M: resultado M-->>P: resolve(resultado) P-->>R: retorno do invoke R->>R: carregarInsumos() R-->>U: Lista atualizada
As duas primeiras trocas (U→R) acontecem só no navegador, sem tocar o banco — é por isso que o modal de confirmação não precisa de IPC.
