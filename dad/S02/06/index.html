Slide 04

Um Padrão, Quatro Operações

O que muda e o que nunca muda

Padrão arquitetural comum ao CRUD
sequenceDiagram participant R as Renderer participant P as preload.js participant M as main.js participant C as conexao.js participant DB as MySQL R->>P: window.api.operacao(dados) P->>M: ipcRenderer.invoke(canal, dados) M->>M: new Promise M->>C: conexao.query(sql, valores, callback) C->>DB: executa SQL DB-->>C: resultado ou erro C-->>M: callback(erro, resultado) M-->>P: resolve ou reject P-->>R: retorno do await
As 4 operações (insumo:criar, insumo:listar, insumo:atualizar, insumo:excluir) seguem exatamente essa mesma sequência.

O que muda

  • O comando SQL (INSERT/SELECT/UPDATE/DELETE)
  • O nome do canal IPC (insumo:criar, insumo:listar...)
  • Os parâmetros passados no array

O que nunca muda

  • A estrutura do new Promise(resolve, reject)
  • Os 3 argumentos de conexao.query (sql, array, callback)
  • O tratamento erro/resultado dentro do callback

Cuidado com o WHERE

O perigo de esquecer o filtro no UPDATE e no DELETE

Slide 05

O WHERE é o Seu Filtro

Sem ele, UPDATE e DELETE afetam a tabela inteira

main.js (dentro do handle)
-- CORRETO: atualiza só o insumo com esse id
UPDATE insumo SET preco = ?, quantidade = ? WHERE id = ?;

-- PERIGOSO: esqueceu o WHERE!
UPDATE insumo SET preco = ?, quantidade = ?;
-- Resultado: TODOS os insumos da tabela recebem
-- o mesmo preço e a mesma quantidade

Por que isso é tão perigoso?

O WHERE é o único filtro entre "esse registro" e "a tabela inteira". Sem ele, UPDATE e DELETE afetam TODAS as linhas — silenciosamente, sem nenhum erro.

Slide 06

Dois Padrões de Comunicação IPC

Mão única vs pergunta-resposta

send/on vs invoke/handle
Característicasend / oninvoke / handle
DireçãoMão única (main → renderer)Pergunta-resposta (renderer pergunta, main responde)
Espera resposta?NãoSim, com await
Onde apareceuAula 4: preencher o modal de ediçãoAulas 2-5: criar, listar, atualizar, excluir
Exemplo de canalinsumo:abrirEdicaoinsumo:criar, insumo:listar, insumo:atualizar, insumo:excluir
Regra prática: se o renderer precisa de uma resposta do banco, é invoke/handle. Se o main só precisa avisar algo, é send/on.

Segurança, Read, Update e Delete

main.js (trecho com problema)
ipcMain.handle('insumo:criar', (event, insumo) => {
  return new Promise((resolve, reject) => {
    const sql = `INSERT INTO insumo (nome, preco, quantidade)
                 VALUES ('${insumo.nome}', ${insumo.preco}, ${insumo.quantidade})`;

    conexao.query(sql, (erro, resultado) => {
      if (erro) reject(erro);
      else resolve(resultado.insertId);
    });
  });
});
  1. Segurança: o código acima tem uma falha grave. Qual é o nome dela e como você corrigiria a query?
  2. Read: o SELECT * FROM insumo devolve um array de objetos pro renderer. O que aconteceria se a tabela estivesse vazia? O carregarInsumos precisa de tratamento especial pra esse caso?
  3. Update: escreva a query UPDATE completa (com ?) que atualiza preco e quantidade de um insumo, dado o id.
  4. Delete: um colega escreveu DELETE FROM insumo sem WHERE dentro de um handle. O que acontece quando esse handler roda? Como evitar esse erro?
