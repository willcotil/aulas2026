Slide 03

O que é o Read?

Pensa num inventário de jogo: os itens que você já tem não são recriados toda vez que a tela abre — eles já existem guardados, e a tela só pergunta pro servidor 'quais itens eu tenho?' pra mostrar a resposta. Read é exatamente isso: perguntar pro banco quais linhas já existem numa tabela, sem criar nada novo.

Definição formal

Read = consultar linhas que já existem numa tabela do banco (SELECT), sem alterar nada — é uma pergunta, não uma mudança.

Slide 04

SELECT: pedindo dados ao banco

Assim como o INSERT da Aula 2, o SELECT também é uma instrução SQL — só que em vez de mandar dados pro banco, ele pede dados de volta. As variações abaixo continuam sendo a mesma tabela insumo.

-- Traz todas as colunas, todas as linhas
SELECT * FROM insumo;

-- Só as colunas que interessam
SELECT nome, valor FROM insumo;

-- Ordenando o resultado (do mais recente pro mais antigo)
SELECT * FROM insumo ORDER BY data_aquisicao DESC;

Sem ? dessa vez

Nenhuma dessas queries tem ? — a Aula 2 usava ? porque dados do usuário entravam na query. Aqui não existe dado de usuário nenhum entrando no SELECT, então não há o que parametrizar.

Slide 05

O retorno do SELECT: um array de objetos

Quando o SELECT roda, o mysql2 não devolve só um valor — ele devolve uma lista de linhas, e cada linha vira um objeto JavaScript. No fim, o resultado é exatamente o padrão que vocês já usam desde o semestre passado: um array de objetos.

formato do resultado
// é assim que o resultado do SELECT chega no JavaScript
[
  { id: 1, tipo: "Filamento", nome: "PLA Branco", valor: 89.9, data_aquisicao: "2026-03-10" },
  { id: 2, tipo: "Resina", nome: "Resina Cinza", valor: 149.5, data_aquisicao: "2026-04-02" }
]

map e filter continuam valendo

É o mesmo array de objetos das Aulas 4 e 5 do semestre passado — então map pra transformar cada insumo numa linha da tabela, e filter (se um dia precisar de busca) continuam funcionando exatamente igual.

Slide 06

main.js: o handler de listagem

Mesma receita da Aula 2: ipcMain.handle devolvendo um new Promise que usa conexao.query. A diferença é que agora não precisamos de array de valores — só do SQL e do callback.

src/main/main.js
ipcMain.handle('insumo:listar', () => {
  return new Promise((resolve, reject) => {
    const sql = 'SELECT * FROM insumo ORDER BY data_aquisicao DESC';

    conexao.query(sql, (erro, resultado) => {
      if (erro) {
        reject(erro);
        return;
      }
      resolve(resultado);
    });
  });
});

Sem insertId dessa vez

No Create, o resolve devolvia resultado.insertId. Aqui o resolve devolve o resultado inteiro — porque no SELECT ele já é a lista de linhas que queremos mostrar.

Slide 07

preload.js: expondo o listarInsumos

O preload.js já existe desde a Aula 2 — hoje só acrescentamos mais uma função no mesmo objeto api.

src/main/preload.js
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('api', {
  criarInsumo: (insumo) => ipcRenderer.invoke('insumo:criar', insumo),
  listarInsumos: () => ipcRenderer.invoke('insumo:listar')
});

Sem argumento

Repare que listarInsumos não recebe parâmetro nenhum — faz sentido, já que listar não precisa de nenhum dado vindo do formulário.

Slide 08

A janela principal também precisa de preload

Até agora, o preload.js só estava ligado às janelas dos modais (Insumo e Peça). Mas a lista vai aparecer na janela principal — e cada BrowserWindow do Electron tem sua própria configuração, então ela também precisa do webPreferences.preload.

src/main/main.js
const criarJanelaPrincipal = () => {
    const janelaPrincipal = new BrowserWindow({
        width: 1000,
        height: 700,
        webPreferences: {
            preload: path.join(__dirname, 'preload.js')
        }
    });

    janelaPrincipal.loadFile(path.join(__dirname, '../renderer/frmPrincipal.html'));
    return janelaPrincipal;
};

Mesmo aviso da Aula 2

Se window.api continuar undefined na janela principal, o motivo de novo é esse: falta configurar o preload daquela janela específica.

Slide 09

frmPrincipal.html: montando a tabela

A tabela usa componentes prontos do Bootstrap — só precisamos de um thead fixo com as colunas e um tbody vazio, que o JavaScript vai preencher.

src/renderer/frmPrincipal.html
<table class="table table-striped table-hover">
    <thead>
        <tr>
            <th>Tipo</th>
            <th>Nome</th>
            <th>Valor</th>
            <th>Data de Aquisição</th>
            <th>Ações</th>
        </tr>
    </thead>
    <tbody id="tbodyInsumos"></tbody>
</table>

Por que o tbody começa vazio

O HTML só desenha a estrutura da tabela. As linhas de verdade — os insumos cadastrados — só existem depois que o JavaScript busca os dados e monta o conteúdo do tbody.

Slide 10

frmPrincipal.js: renderizando as linhas

Mesmo padrão de map + template string + join('') que vocês já usaram na Aula 5 do semestre passado — só que agora os dados vêm do banco de verdade, via window.api.listarInsumos().

src/renderer/frmPrincipal.js
const carregarInsumos = async () => {
    const insumos = await window.api.listarInsumos();
    const tbody = document.querySelector('#tbodyInsumos');

    if (insumos.length === 0) {
        tbody.innerHTML = '<tr><td colspan="5">Nenhum insumo cadastrado.</td></tr>';
        return;
    }

    tbody.innerHTML = insumos.map((insumo) => `
        <tr>
            <td>${insumo.tipo}</td>
            <td>${insumo.nome}</td>
            <td>${insumo.valor}</td>
            <td>${insumo.data_aquisicao}</td>
            <td>—</td>
        </tr>
    `).join('');
};

carregarInsumos();

E se a lista estiver vazia?

Sempre trate o caso de lista vazia — sem isso, o usuário vê uma tabela sem cabeça nem pé, sem entender se deu erro ou se realmente não há nada cadastrado ainda.

Slide 11

Tratamento: formatando moeda e data

Repara no resultado: o valor aparece cru (tipo 89.9, sem R$ nem vírgula) e a data vem como o MySQL guarda por dentro, não como dd/mm/aaaa. Duas funções pequenas resolvem isso.

src/renderer/frmPrincipal.js
const formatarMoeda = (valor) => `R$ ${Number(valor).toFixed(2)}`;

const formatarData = (data) => {
    const d = new Date(data);
    const dia = String(d.getDate()).padStart(2, '0');
    const mes = String(d.getMonth() + 1).padStart(2, '0');
    return `${dia}/${mes}/${d.getFullYear()}`;
};

// dentro do map, troque:
// <td>${insumo.valor}</td>           por  <td>${formatarMoeda(insumo.valor)}</td>
// <td>${insumo.data_aquisicao}</td>  por  <td>${formatarData(insumo.data_aquisicao)}</td>

Por que a data precisa de tratamento

O MySQL guarda datas num formato interno; o driver mysql2 normalmente entrega isso como texto no padrão ISO ou como um objeto Date — nenhum dos dois é o dia/mês/ano que a gente está acostumado a ler.

Slide 12

E quando a lista fica velha?

Cadastrou um insumo novo no modal e voltou pra janela principal — mas a lista continua com os dados de antes. Faz sentido: carregarInsumos() só roda quando a página carrega, não sabe que algo mudou em outra janela.

Soluções simples de hoje

  • Recarregar a lista sempre que a janela principal ganhar foco (evento focus).
  • Ou um botão simples 'Atualizar' que chama carregarInsumos() de novo.

Pra quem quiser ir além

Sincronizar duas janelas automaticamente, sem precisar de foco ou botão, é possível com o padrão de 'rádio inverso' visto na Aula 13 do semestre passado — mas isso é avançado, não é o esperado pra hoje.

O padrão do Read

preload expõe → webPreferences liga → handle roda o SELECT → resolve devolve o array → Renderer transforma em linhas de tabela. O mesmo caminho vale pra qualquer listagem da disciplina, inclusive a de Peça Impressa no exercício de hoje.

Desafios

Agora é sua vez: listando Peça Impressa

Aplique o mesmo padrão de hoje pra tabela peca_impressa: um SELECT no main.js, uma função exposta no preload.js, e uma tabela nova na janela principal pra mostrar as peças cadastradas.

  1. No preload.js, exponha listarPecas: () => ipcRenderer.invoke('peca:listar') — mesmo padrão do listarInsumos, no mesmo objeto api.
  2. No main.js, crie o ipcMain.handle('peca:listar', ...) fazendo um SELECT * FROM peca_impressa — mesma receita do handler de insumo de hoje, reaproveitando a conexao.
  3. Em frmPrincipal.html, adicione uma segunda tabela (com seu próprio tbody) pra listar as peças.
  4. Em frmPrincipal.js, crie carregarPecas, no mesmo padrão de carregarInsumos: map + template string + join('') no innerHTML.
  5. Trate a formatação do peso, do tempo de impressão e da data das peças — mesma ideia do formatarMoeda e do formatarData de hoje.
  6. Teste cadastrando e listando pelo menos 3 peças, conferindo se os dados aparecem certinho e já formatados na tabela.

Dica

Se window.api.listarPecas não existir, cheque na ordem: o preload.js expõe a função? o main.js tem o webPreferences.preload na janela certa? o handle('peca:listar') está registrado?
